# AGENTS.md — Global Core Rules

## Scope

These rules apply to ALL projects regardless of type, size, language, or lifecycle.

Project-level AGENTS.md can add more rules but cannot weaken these.

---

## 优先级

Safety > Correctness > Evidence > Minimal > Consistency

证据层级：测试通过 > 静态分析/类型检查通过 > 代码读取确认 > 文档/注释参考 > 持久化记忆/MCP上下文 > 内部知识（最低，需标注"未验证"）

---

## Principles

- **KISS**: Prefer simple, readable code. AI tends to over-engineer — resist the urge.

---

## Always (必做)

| 规则         | 说明                                                |
| ------------ | --------------------------------------------------- |
| 先读后改     | 编辑任何文件前必须读取其当前内容                    |
| 错误可见     | 所有异常处理必须有可见后果（日志/重抛/用户反馈）    |
| 验证外部数据 | API响应、文件读取、子进程输出必须验证后使用         |
| 可逆性原则   | 修改前确认可恢复（VCS、备份、快照或设计上的可逆性） |
| 文件冲突检测 | 并行任务修改同一文件时必须串行执行；派发前确认各任务无共同修改文件 |
| 修改范围受限 | 只修改任务明确指定的文件，不得修改未提及的文件 |

---

## Ask First (先问)

| 条件              | 触发场景                                       |
| ----------------- | ---------------------------------------------- |
| 歧义 >2种合理意图 | 用户指令有多种解释                             |
| 影响范围大        | 重构、架构变更、跨多文件修改                   |
| 破坏性操作        | 删除数据、强制推送、生产环境部署、数据库清空等 |
| 外部依赖          | 添加外部依赖或集成第三方服务                   |
| 操作项目外文件    | 修改workspace外的路径                          |
| 连续失败3次       | 停止，报告已尝试方案，请求用户介入             |

---

## Never (绝对禁止)

| 规则                | 说明                                                                          |
| ------------------- | ----------------------------------------------------------------------------- |
| 禁止捏造            | 不编造路径、API、配置键、环境变量、测试结果                                   |
| 禁止绕过验证        | 不削弱断言、不跳过测试、不静默忽略失败                                        |
| 禁止空 catch        | catch(e) {} 会吞掉错误，必须有日志/重抛/用户反馈                              |
| 禁止删除测试        | 不允许删除/跳过/削弱测试来让测试套件变绿，必须修复代码本身                    |
| 禁止暴露密钥        | 不记录、导出、嵌入凭证/令牌/密钥                                              |
| 禁止未确认持久化    | 代码提交、包发布、生产部署等持久化操作需用户明确请求                          |
| 禁止LLM自动写入规则 | 防止 Agent 为完成任务自改规则；LLM 可分析/建议，但写入 AGENTS.md 须经人工确认 |

---

## 规则演进原则

"如无必要，勿增实体"。规则和信息的必要性判断与迭代：

- **解决过实际失败吗？** — 无失败记录则不设规则
- **有唯一归属吗？** — 信息只在一处写，其他位置引用
- **放在最具体层级了吗？** — 代码逻辑 > 项目规则 > 全局规则
- **定期修剪** — 每条规则/信息都有维护成本，过时即删

**迭代流程**：从最小开始 → 使用 Agent → 记录失败 → 添加规则到正确层级 → 修剪 → 重复
